Club Ladder Data API changelog

What changed in each version of the API. The full reference is the documentation.

0.3.1: Freshness

2026-10-09

  • Responses may now be up to 60 seconds old, up from 15: the roster, matches, ratings and seasons up to 60 seconds, tournaments, sessions and club events up to 30. A member's opt-out or deletion request reaches the feed within the same 60 seconds.
  • A recent answer is reused only for the same consumer, and the same request written differently (an upper-case id, a timestamp with or without seconds) counts as the same request.
  • A registration import refreshes your tournament entrant lists and event signups at once. A prediction write changes nothing you read.
  • Under heavy load a request may wait briefly for the database; one that cannot be answered within 5 seconds is a 503 as before.

0.3.0: Registrations

2026-10-09

  • A second write: POST /v1/registrations delivers one response from a Google Form an exec has bound to a tournament or a club event. It needs the new registrations:write scope, meant for the club's own form script; no existing key carries it.
  • Each entry is answered entered, pending or refused, and a refusal names only something about the event. A member is never entered by a form: they confirm the entry in the club app.
  • The same response sent again answers from the record with replayed: true; an edited response replaces the earlier one. A form with no active binding for the key is a 404.

0.2.0: Predictions

2026-10-09

  • The first write: POST /v1/predictions stores head-to-head win predictions from your model, and DELETE /v1/predictions removes your own. Both need the new predictions:write scope, which no existing key carries unless an exec adds it.
  • A prediction names a singles or doubles matchup by player_ref, side A's chance of winning, a model name and made_at. A matchup is two unordered sides, so predicting it again replaces the earlier row.
  • Up to 100 items a call. Each one is answered created, replaced or refused; the call is 422 with the same body when anything was refused.
  • New errors on the write: 413 for a body over 64 KiB and 415 for a body not sent as application/json.
  • Writes are never served from the read cache, and predictions never change a rating or a statistic.
  • A member may see a prediction in the club app only for a challenge they play in, labelled as one with its model and time, never with the consumer that made it.

0.1.0: First public version

2026-10-09

  • Read-only, keyed access to club data. Each key is limited to the scopes it was granted: players:read, matches:read, ratings:history:read, seasons:read, tournaments:read and schedule:read.
  • Players appear under a pseudonymous player_ref that is different for every consumer.
  • Roster: /v1/players and /v1/players/:ref.
  • Matches: /v1/matches, /v1/matches/:match_ref, a player's matches, head-to-head (/v1/players/:ref/vs/:other_ref), per-season records and rating history.
  • Seasons: /v1/seasons, /v1/seasons/:id and standings.
  • Tournaments: /v1/tournaments, a tournament, and an event with its entrants and draw, including staged events and external teams.
  • Schedule: /v1/sessions and /v1/events (club events), filtered by from and to.
  • /health and this API's documentation at /documentations need no key.
  • This changelog at /changelog, also keyless.
