# Release 1.0.5

1.0.5 is the sign-in hotfix: a fresh email code is no longer reported as expired, and a passkey button that cannot work inside another app's browser now says so. It reached production on 2026-09-26.

Compared with 1.0.4. The code fix first reached production on 2026-09-25, and the fees search and `/config ping_roles` on 2026-09-22, in builds still numbered 1.0.4; this is the release that records them.

## For members

- A fresh sign-in code is no longer reported as expired. A new member whose account was not yet confirmed was told their code had expired; it is now tried the right way, on the member site and in the console.
- Inside another app's built-in browser (Instagram, Facebook and similar), where a passkey cannot work, the page now says so: open it in Safari or use an email code. Passkey autofill skips those browsers too.

## For execs and admins

- Search the Club fees table by name or email. Select-all follows the search, so a bulk action only touches the members on screen.
- `/config ping_roles` in Discord sets the role each session ping mentions (`every_session` fills all three groups).

## Under the hood

- Failed passkeys and failed email codes are reported to Sentry, tagged by flow and stage, with no email, code or member id in the event.
- The member data export counts rows by a named column, which a column-granted table requires; before it, every export failed in testing once 00241 was applied. This fix reached production in the same update as 1.0.4.
